# Session log — 2026-06-14 — Gate 0 / P1.1 (Unify skill IDs)

Goal: Make `skill-registry-v2` the single source of truth for AI skill IDs and remove
legacy aliases — the first real exercise of the Bài 0E dev-agent layer on production code.

Branches: `lesson/gate0-p1.1` (1a/1b/1c), `lesson/gate0-p1.1-bis` (alias cleanup + ADR);
both merged to master. Plus master-level hygiene commits (LF normalization, agent tools,
junk removal, colors).

## Why

Skill IDs were written as raw string literals duplicated across many files (components +
the `run-skill` route), which invites drift and typos. The registry existed but wasn't the
enforced source. Gate 0 ("architecture cleanliness") wants one source of truth + no legacy
aliases, so later AI work builds on a clean foundation.

## Slices (smallest change, human approves each)

- **Audit** — mapped every skill-id literal and found the real legacy aliases in the route.
- **1a** — added `AI_SKILL_IDS` (canonical map) + `AISkillId`; typed the registry against it
  so any drift fails typecheck. Additive, zero behavior change.
- **1b** — 5 components import `AI_SKILL_IDS` instead of local string consts.

  (Group B, deferred to P1.3) and the provider-namespace `ai-template-review` (Group C).

## Problems hit and how we solved them

1. **Whole-file diffs (CRLF churn).** Cowork wrote LF into CRLF/mixed files → thousands of
   spurious changed lines. Root cause: the repo had mixed line endings. Fix: a one-time
   repo-wide LF normalization (`.gitattributes` `* text=auto eol=lf` + `git add
   --renormalize`), and route code edits through the native subagent.
2. **Subagent edits didn't persist (twice).** The agent claimed success but `git diff` was
   empty. Root cause: agent definitions used lowercase tool names (`[read, edit, bash]`);
   Claude Code expects `Read, Edit, Bash`. Fix: corrected to PascalCase + restart; verified
   the subagent then wrote a real diff.
3. **Brief had the wrong scope.** The first 1c brief assumed `file-to-draft-ptr` etc. were
   dead aliases (based on reading only ~95 lines of a 4147-line file). The reviewer subagent
   read the real file and showed they were live translation logic. Fix: narrowed 1c to the
   decided template-review change; deferred the alias removal to an investigated 1c-bis.
4. **"No legacy aliases" is partly architectural.** Investigation split the remainder into
   Group A (safe to remove), Group B (`ptr-to-brd-outline`: registry-entry-vs-alias
   contradiction), Group C (provider-namespace key). Fix: ADR + remove only Group A; defer
   B/C with rationale — avoiding scope creep per `NO_EXTRA_INTERMEDIATE_STEPS_RULE`.
5. **Accidental empty files** (`AI_SKILL_IDS.*`) committed during an earlier sed mishap →
   `git rm` cleanup commit.

## Lessons for next time

1. **Verify `git diff` yourself** — never trust a subagent's summary; the reviewer caught
   both a non-persisting edit and a wrong scope by reading ground truth.
2. **Small change ⇒ small diff.** A blown-up diff means a line-ending (or tooling) problem,
   not real work. Stop and fix the cause.
3. **Code edits via the native subagent; Cowork for plan / brief / review / docs.** Cowork
   writing into the repo caused the CRLF churn.
4. **Normalize line endings early** in a mixed repo; it removes a whole class of noise.
5. **Check agent config** (tool names, foreground vs background) before trusting subagent
   output.
6. **Record scope decisions as an ADR** instead of over-cleaning.
